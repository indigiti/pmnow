# PMNow M13–M15 Product Contract

These milestones extend the existing No-DB, UUIDv7, repository/service-boundary architecture. Community content, utility data and events remain separate domains from canonical newsroom Story records.

## M13 — Community
Goal: neighbourhood participation without weakening newsroom trust boundaries.

Foundation:
- community posts scoped to Pune neighbourhoods
- post types: update, question, recommendation, alert
- moderation-first publishing; submissions default to pending
- reader reports
- newsroom moderation queue
- My Pune area integration
- analytics and notification hooks
- no direct conversion of UGC into canonical Story records

## M14 — Utilities expansion
Goal: move the M12 Utility Layer from manual/product foundation toward production-grade freshness.

Foundation:
- provider adapter contracts for official traffic/transit/civic/weather/AQI sources
- freshness TTLs and live/stale/expired states
- idempotent external IDs and ingestion
- source health/SLA telemetry
- automatic expiry/resolution policy
- provider failures isolated from public rendering

The first code slice adds UtilityFreshnessService. Existing M12 source/provider TODOs move here without changing M12 data contracts.

## M15 — Events
Goal: a dedicated Pune events/discovery domain.

Foundation:
- structured event records separate from news Stories
- venue, neighbourhood, category, start/end, provenance
- upcoming/expired lifecycle
- public-only discovery
- newsroom-managed publishing
- later My Pune ranking, save/follow and reminders

## Architecture invariants
- No database requirement before the planned platform/data milestone.
- UUIDv7 canonical IDs.
- Controllers/UI never read storage files directly.
- UGC is never treated as verified newsroom reporting by default.
- External source URLs must be HTTP(S).
- State-changing browser APIs remain CSRF/same-origin protected.
