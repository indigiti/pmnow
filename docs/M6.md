# M6 — Newsroom Release

M6 turns the M1–M5 content platform into an operational No-DB newsroom layer while preserving the public Story/API contracts.

## Included

### Editorial workflow

Workflow states supported by the content objects and editorial actions:

- `ready`
- `review_required`
- `published`
- `rejected`
- `duplicate`
- `archived`
- `hidden`

Actions are append-audited in `storage/data/editorial-actions/` and `storage/events/editorial-*.jsonl`.

Approval calls the existing M5 intelligence/cluster pipeline and publishes the canonical Story object used by Home, Search and Watch.

### Newsroom/RBAC foundation

Admin pages:

- `/admin`
- `/admin/inbox`
- `/admin/sources`
- `/admin/jobs`
- `/admin/notifications`

Roles:

- `super_admin`
- `admin`
- `editor`
- `reviewer`
- `viewer`

`ADMIN_DEV_BYPASS=true` is intended only for local development. Set it to `false` outside development and use the configured bootstrap account.

### Source operations

Source administration supports:

- list/health state
- create source
- update source API
- delete source API
- test connector
- sync connector
- sync schedule fields

Credentials remain environment references rather than values stored in source JSON.

### Queue / scheduler

No-DB jobs live in `storage/data/jobs/`.

Scheduler:

```bash
php tools/scheduler.php
```

Worker:

```bash
php tools/worker.php
```

The current executable job type is `SOURCE_SYNC`. Retry backoff is 1m, 5m, 15m, 30m, 60m and each job records attempts/status/error/result.

### Search index

`storage/indexes/search.json` is a rebuildable inverted index over published stories. The public endpoint remains:

```text
GET /api/v1/search?q=metro
```

Manual rebuild:

```bash
php tools/rebuild-search.php
```

The query service also detects a stale index after story changes and rebuilds it.

### Follow notifications

A Story follow can receive notification records in `storage/data/notifications/`. Live demo updates now notify followers of the underlying Story.

Public surfaces:

- `/notifications`
- `GET /api/v1/notifications`
- `POST /api/v1/notifications/{id}/read`

### M6 contracts

New shared contracts:

- `contracts/editorial-action.schema.json`
- `contracts/job.schema.json`
- `contracts/notification.schema.json`

## Testing

With FastAPI running:

```bash
php tools/seed.php
php tests/smoke.php
php tests/m4_m5_smoke.php
php tests/m6_smoke.php
```

M6 smoke verifies RBAC bootstrap, editorial approval/publication, editorial audit persistence, filesystem search, scheduler enqueue, worker execution and follow-notification persistence.
